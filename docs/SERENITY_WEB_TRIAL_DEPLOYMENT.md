# Staging deployment

Build React in `apps/web` with `VITE_TRIAL_MODE=staging`, a WSS `VITE_REVERB_URL` and the public `VITE_REVERB_APP_KEY`: run `npm ci && npm run build`. Serve `dist/` over HTTPS with unknown application routes falling back to `index.html`. Reverse-proxy `/api/*` and `/web/*` on the same web origin to the dedicated staging Laravel service. Keep session cookies HttpOnly, Secure and SameSite=Lax; the React client fetches CSRF tokens through `/web/csrf`. Set Laravel `APP_ENV=staging`, `APP_DEBUG=false`, dedicated DB and secrets, `SESSION_SECURE_COOKIE=true`, and exact `REVERB_ALLOWED_ORIGINS`; run migrations before health and contract checks. Never bundle Reverb secrets or database credentials in Vite variables.

Host Laravel HTTP, a queue worker and Reverb as separately supervised processes on infrastructure that supports long-lived processes. Configure TLS and WSS proxy upgrades. A static host alone cannot run those services. Do not publish the site or seed genuine client records without approval. Default staging retention proposal: test account and community content deleted after 30 days of inactivity; logs after 14 days; backups after 30 days. Governance must approve retention, moderation roles, incident response, support contacts and therapist verification before external testing.
